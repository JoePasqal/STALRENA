# STALRENA v1 — отчёт о реализации и проверках

Дата сборки отчёта: 26.11.2026. Движок: **Godot 4.4.1-stable (official, `49a5bc7b6`)**, GL Compatibility.
Среда проверок: контейнер Linux (4 vCPU Intel Xeon 2,1 ГГц, без GPU, программный OpenGL `llvmpipe`, Xvfb). **Человек игру на этой среде не запускал.** Все «прохождения» ниже — автоматические (автопилот `BotInput`), если не сказано иное. Скриншоты в `docs/screenshots/` сняты с реально запущенного проекта (не концепты), графика на них — процедурные заглушки.

## Что реализовано (этапы A → B → C)

* **A**: проект, ввод (клавиатура/мышь, сенсорные стики), оружие, враги, аптечка, магазин из шести карточек, броня, части, волны, пауза, итоги.
* **B**: семь видов оружия × 5 рангов, три брони, 12 модулей и 4 набора, полный магазин (обновить/замок/pity/уровни 1–5), восемь ролей врагов, босс, сектора по 12 волн, сохранения с backup, возобновление боя.
* **C**: три локации (6 раскладок, вода −15%, паровые клапаны с предупреждением 1,2 с), три босса с фазами, элита (3 свойства, максимум одно), модификаторы повторных секторов, мастерство (+5% аддитивно, один раз за магазин), настройки качества/FPS/автоприцела, сенсорный UI с мультитачем, debug-переходы на волны 24/60/120, баланс-лог, Android-пресет и debug APK.

## Android

Сделано в среде разработки:

1. Скачаны официальные шаблоны экспорта 4.4.1.stable (1,2 ГБ) и установлены локально.
2. Официальный Android SDK (`dl.google.com`) из контейнера недоступен (прокси закрывает хост). Вместо него: JDK 17 и пакеты Ubuntu `apksigner 31.0.2`, `adb`, `zipalign`, из которых вручную собрана папка со структурой SDK (`platform-tools/adb`, `build-tools/34.0.0/{apksigner,zipalign}`), на неё указал `export/android/android_sdk_path`. Debug-keystore — стандартный `androiddebugkey`, созданный `keytool` локально (не коммитится).
3. Экспорт: `godot --headless --path . --export-debug "Android debug" build/stalrena-debug.apk` → «Signed», `apksigner verify` → Verifies. APK содержит `lib/arm64-v8a/libgodot_android.so`, игровые данные и пакет `com.joepasqal.stalrena`; в манифесте найдено только разрешение `android.permission.DUMP` (добавляет debug-шаблон), сетевых нет.
4. Важная находка: без `rendering/textures/vram_compression/import_etc2_astc=true` экспорт останавливается с пустым сообщением об ошибке; настройка включена в `project.godot`.

**Не сделано / блокеры:** установка и запуск APK (нужны устройство или эмулятор; `adb` в контейнере не видит устройств), официальный SDK не использовался (поэтому совместимость именно с официальными build-tools не подтверждена), release-подпись (ключи владельца), AAB. APK в репозиторий не коммитится (`build/` в `.gitignore`); воспроизведение — команды в README.

## Производительность (ACCEPTANCE 33)

Среда: 4 vCPU Xeon 2,1 ГГц, `llvmpipe (LLVM 20.1.2)` — **программная** отрисовка в Xvfb 1280×720, vsync выключен, качество «высокое». Сцена: ~36 живых мобов постоянно (десять типов, включая стрелков и носителей), LMG, поздняя волна (HP врагов ×7,5), автопилот.

* 900 кадров: средний кадр **24,3 мс (≈ 41 FPS)**, p95 30,8 мс, p99 40,3 мс; режим «низкое качество» — 24,7 мс (разница в пределах шума: узкое место — программный растеризатор).
* Только игровая логика (без отрисовки, `sim.tscn`): **≈ 0,3–1,1 мс на шаг** при 36 мобах.
* Это не показатель телефона: на реальном Android среднего уровня результат может быть как лучше (GPU), так и хуже (слабый CPU). 60 FPS не обещается; профилирование на устройстве — **оставшийся шаг**.

## Оставшиеся ограничения и честные оговорки

* **Графика временная**: 58 записей manifest, ни одного готового PNG (`docs/ART_STATUS.md`). Анимации тела — покачивание заглушки; атласы настоящих кадров поддерживаются раскладкой по умолчанию (см. `assets/art/README.md`), но не проверялись на реальных кадрах. Шаблонные пути ресурсов проверены только на подмене одного PNG.
* **Баланс — стартовые гипотезы**: длительность волн и сложность проверены только автопилотом; плейтест людьми не проводился. В тюнинг-данные вынесено всё, кроме формул (они в `StatCalc`/`WaveMath`).
* **Звук**: только простые процедурные сигналы (громкость эффектов работает); музыки нет, ползунок «музыка» зарезервирован.
* **Настройки «Подсказки»**: показывают тексты первого появления врагов и подсказки управления; пиктограмм врагов нет (только текст).
* **Элитные пиктограммы**: контур и ромб над врагом; цвет по свойству.
* `Telegraph` как отдельная сцена не выделен: телеграфы врагов рисуются самим врагом, поля босса/арены — `HazardLayer` (программные, чёткий контур), как допускает контракт.
* Не профилированы утечки пулов/таймеров/соединений при долгом забеге (сцены освобождаются при смене волны; специальных тестов на утечки нет).
* Сенсорный ввод написан по документации Godot (`_gui_input`, события по индексам пальцев), но без реальных касаний не проверялся. Раскладка кнопок может потребовать подгонки под устройство.
* Обработка «безопасной области» реализована для HUD и сенсорных кнопок; экран магазина использует фиксированные отступы.
* Ограничение `DisplayServer`-зависимых функций: `get_display_safe_area()` в headless возвращает пустую область — вырез не проверялся.
