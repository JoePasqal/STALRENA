# STALRENA — договорённость о графике v1

## Выбранная подача

Владелец выбрал вариант 4: детализированная 2D с нарисованным объёмом. Настоящие 3D-модели не нужны. Камера неизменна, смотрит сверху под углом, видны головы, плечи и часть передней поверхности тела. Игровые координаты обычные 2D, без обязательной изометрической сетки. Условная высота камеры и свет согласованы у всех объектов. Вдохновение — читаемость тактических шутеров, оригинальный постапокалиптический мир.

Палитра окружения: бетонные серые, грязно-зелёные, ржавые коричневые. Герой отделяется по светлоте. Вражеские телеграфы — контрастные красно-оранжевые, дружественные эффекты — голубые/светлые. Не маскировать опасный контур сложной текстурой. Освещение сверху-слева, слабый рассеянный свет; резкие длинные нарисованные тени в спрайтах не использовать.

Рисунки создаёт ChatGPT, код интеграции — Claude. Отсутствие финального PNG не блокирует игру. Ассет из генератора считается художественным исходником, пока не проверены размер, прозрачность, pivot, ракурсы и поведение в игре. Концепт не является готовым анимационным атласом и не объявляется скриншотом проекта.

## Важное ограничение объёма

Не заказывать отдельные полные анимации для каждого из пяти рангов и каждой пушки. Ранги различаются иконкой, цифрой, небольшими накладками/цветом. Оружие отдельное. Начальная поставка может содержать один статичный корпус и простую временную анимацию, а механики остаются полностью играбельными. Обязательные игровые действия не зависят от готовности всех кадров.

## Реестр и fallback

`assets/asset_manifest_v1.json` — спецификация ожидаемых файлов, а не доказательство их наличия. Все записи из этого пакета имеют статус `planned`. PNG здесь не поставляются. Использовать AssetRegistry, который по ID возвращает текстуру, кадровую разметку, pivot, локальный масштаб и socket-координаты. Нет файла → читаемый placeholder того же логического размера и запись в диагностике один раз. В бою не спамить ошибками.

Статусы интеграции: planned → source_received → prepared → integrated → verified. Новую картинку сначала подготовить и проверить, затем менять ссылку в реестре. Финальные размеры не угадывать из генерации; подготовка может включать ручной отбор/правку. Не растягивать маленький исходник до требуемого кадра без визуальной проверки. Путь к изображению не использовать как ID предмета.

## Единицы и сетка

- Базовое пространство UI — 1280×720, игровые мировые единицы совпадают с логическими пикселями сцены, независимы от физических пикселей телефона.
- PNG — RGBA, прозрачный фон у персонажей, оружия, предметов и декораций.
- Детализированная графика: фильтрация linear по умолчанию, согласованный масштаб, без обязательного nearest/pixel-grid.
- Атлас: одинаковые клетки, минимум 4 px прозрачного padding/extrusion для предотвращения bleed. Нельзя подрезать каждый кадр так, чтобы pivot прыгал.
- Снизу вверх по Y: `y_sort` по опорной точке ног, высокие объекты разделять на основание/верх.
- Все размеры ниже — целевой подготовленный формат, а не обещание точного вывода генератора.

## Герой

Кадр 256×256. Опорная точка ног `(128,208)`; world scale по умолчанию 0,5, итого клетка 128×128 мировых единиц. Примерная фигура занимает 130–160 px по высоте исходника. Коллизия ног radius=12 в игровых единицах, не следует за шириной плеч. Нормальное тело, без чиби-пропорций; серо-зелёная одежда, защитная маска, перчатки. В тело не впекать оружие.

Начальный целевой набор направлений: S, E, N; W допустимо зеркалировать из E, если нет заметных асимметричных обозначений. Тело выбирает одно из четырёх направлений по прицелу, оружие поворачивается непрерывно. Прицел и хитбокс не зависят от частоты кадров тела. Движение назад допускается с тем же циклом ног на первой версии.

На каждое исходное направление: idle 1 кадр, walk 4 кадра на 8 FPS, hit 1. Смерть — общий отдельный ряд 4 кадров, после которого можно показывать статичное тело. Общая цель первого полного набора — 22 кадра, а не сотни вариантов. Если готов только один ракурс, использовать временную графику остальных направлений.

Ряд/направление и сокеты хранить в метаданных, не зашивать магические индексы в Player.gd. Слои: тень → ноги/тело → часть оружия за телом при направлении N → броневые накладки → часть оружия перед телом при S/E/W → эффекты. В каждой исходной ориентации есть weapon_socket; исходный ориентир `(155,145)` для E, но финальную точку корректируют по реальному рисунку. Непрерывный поворот оружия не вращает тело целиком.

Броня: три семейства визуальных накладок/вариантов корпуса. На первой итерации достаточно простых читаемых накладок для всех рангов одной ветки. Источники кадров и небольшие offsets допускаются в реестре. Броневые изображения не меняют фактические размеры hitbox.

## Оружие

Отдельный кадр 256×128, фон прозрачный. Направление исходника вправо, точка хвата `(64,64)`, дульная точка `(224,64)`. Scale 0,25 → игровая длина между хватом и дулом 40 единиц. Для пистолета/огнемёта допускаются свои значения, явно записанные в метаданных. Не отражать оружие по X для поворота; для левой стороны поправить вертикальное отражение и порядок слоёв, чтобы оно не оказалось вверх ногами. UI-иконка оружия — отдельный 256×256 PNG, а не растянутый кадр боя.

Ранговая смена изображения необязательна: сначала один боевой спрайт на ветку, пять вариантов карточки/цветовой метки. Не запекать текст «V», стоимость или числа урона в картинку.

## Враги и боссы

Обычные враги: 256×256, pivot feet `(128,208)`, default scale 0,5, собственный hit radius в балансе. Для бегунов/животных возможен pivot на середине нижней опорной линии с отдельной записью. Вид атаки читается по позе, но её фактический telegraph рисует код.

Целевой комплект: idle/move/attack/death; направления S/E/N и зеркальная W там, где это корректно. Для первого запуска можно статичную графику с временными эффектами движения. Не рассчитывать попадание по видимому кадру: Combat использует отдельные таймеры и коллизии. Для элиты тот же базовый спрайт плюс контур/иконка, без нового атласа.

Боссы: кадр 512×512, pivot `(256,416)`, default scale 0,5. Радиусы атак и коллизии из баланса. Несколько отдельных поз приемлемы до готовности полных анимаций.

## Окружение

Земля — бесшовные 512×512 текстуры без перспективных линий и объектов, которые должны иметь коллизию. Мелкие объекты — 256×256, крупные 512×512, alpha, pivot на основании. Стены/штабеля отдельно от пола. Изображение не определяет форму коллизии: она задаётся в сцене и проверяется на проходимость.

Лесопилка: грунт, бетон, штабеля, ящики, металлическое ограждение, сломанная машина. Насосная: бетон, трубы, блоки, клапаны. Затопленный двор: грязь, вода, камыш/трава на краю маршрутов, обломки. Одна большая картинка целой карты не подходит: нужны отдельные объекты и поверхности для перестановки.

## UI и эффекты

Иконки предметов — 256×256 с alpha и безопасным полем 16 px. На карте/в магазине уменьшаются до 64–96 логических px. Силуэт узнаваем в 64 px. Предмет показан один, без рамки редкости, текста, цены и декоративной сцены. Рамки, ранги, проценты, подписи, 0/3 и кнопки рисует код.

Телеграфы кругов/конусов/линий сначала программные, чёткие и масштабируемые. Изображения дыма/вспышки могут быть отдельными PNG/короткими атласами. Опасные зоны имеют чёткий край, а не только полупрозрачный дым. Тень персонажа — отдельный спрайт или простой ellipse.

## Порядок художественных поставок

1. Визуальный ориентир героя и одной арены; это концепт для проверки выбранного стиля.
2. Статичный герой, пистолет/карабин, бродяга/бегун/плевун, пол/три препятствия, аптечка — чтобы заменить основные placeholders.
3. Анимации героя, остальные оружия и враги, все иконки магазина.
4. Боссы, окружение следующих локаций, косметические ранговые варианты и эффекты.

Claude после первого запуска возвращает один скриншот с масштабом героя, размеры текущих кадров, offsets и список реально нужных ассетов. Если текущий рисунок расходится с контрактом, сообщить конкретное расхождение, не молча менять весь масштаб мира. Готовый код и готовый художественный набор — разные критерии: в отчёте явно указать, какие изображения временные.
