# STALRENA — полное задание на реализацию v1

## 0. Результат работы

Создать работающий проект одиночной мобильной игры на Godot 4.x и GDScript. Основная платформа — Android, обязательна возможность проверить игру на ПК клавиатурой/мышью. Офлайн, без аккаунтов, серверов, PvP, рекламы и платежей в v1.

Код пишет Claude. Художественные изображения готовит ChatGPT отдельными поставками. Реализовать игру с заменяемыми временными спрайтами, не блокируя механику ожиданием арта. Финальный стиль — детализированная 2D с нарисованным объёмом, фиксированная камера сверху под углом. 3D-модели и 3D-физика не нужны.

Сначала изучить инструкции и содержимое репозитория. Если движок уже закреплён появившимися файлами — сохранить совместимость и описать отклонение. Для пустого репозитория выбрать доступную стабильную версию Godot 4, записать точный номер в README и использовать одинаковые editor/export templates. Не придумывать номер будущей версии. Предпочтительный renderer — Compatibility; подтвердить соответствие требуемым эффектам и Android-экспорту. Не подключать тяжёлые плагины и сетевые зависимости без необходимости.

Документация движка: https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html и https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_android.html . Конкретные флаги и требования проверять по документации выбранной версии.

## 1. Игровое обещание и границы

Герой выживает на небольших аренах. За волны получает монеты. Между волнами тратит их на случайные предложения магазина, покупает снаряжение и части, собирает более сильные версии оружия/брони, строит сочетания пассивных модулей. Затем встречает всё более опасные составы врагов и боссов. После босса меняется локация; забег продолжается без последней волны.

Поражение — ХП героя достигло нуля. Никакого алтаря, реликвии, базы для защиты или команды игроков. Герой перемещается свободно; «защищать себя» не означает стоять неподвижно.

Сложность повышается по номеру волны. Составы и раскладки разнообразны, но навсегда догонять мастерство игрока скрытым усилением во время боя нельзя. Поддерживается длинный забег, а не обещание бесконечного нового контента.

## 2. Состояния и цикл

`MainMenu → NewRun/Continue → Shop → WaveIntro → Combat → WaveComplete → Shop`. На двенадцатой волне сектора — BossCombat; победа переводит в Shop следующей локации. Из Combat доступны Pause и GameOver. Переходы идемпотентны: двойное событие смерти последнего моба не должно дважды начислять награду или открыть два магазина.

Перед первой волной: 100 монет, пистолет «Искра» I, 100/100 ХП, без брони, магазин уровня 1, две ячейки пассивных модулей, одна аптечка. Первый магазин доступен до начала боя.

Победа в обычной волне: очередь появления исчерпана, все обязательные враги мертвы и опасные вражеские снаряды/поля удалены с коротким безопасным завершением. Не ждать исчезновения декоративных эффектов или необязательных остатков. Призванные обязательные существа входят в завершение, но не дают отдельного дохода.

Вход в магазин после победы: ровно одно начисление монет; полное восстановление здоровья; сброс статусов, перезарядка оружия; обновление предложений, кроме заблокированного магазина. По кнопке «Начать волну» — полное здоровье по текущему максимуму, полный магазин патронов и ровно одна аптечка. Покупать, продавать, экипироваться и выбирать модули можно только в Shop.

Бой ведётся до зачистки, без жёсткого таймера поражения. Время волны используется для статистики и отладки. Цель длительности — примерно 40–90 секунд для обычных волн, но подтвердить это только плейтестом. Последний застрявший моб отмечается указателем; если он недостижим из-за ошибки пути, корректно переставить его на достижимую точку с предупреждением появления.

## 3. Управление и интерфейс

Горизонтальная ориентация, базовое логическое пространство 1280×720, адаптация под 16:9–20:9 и safe areas. Карта больше экрана, камера следует за героем и ограничена границами арены; не вращается. Никакой обязательной тряски экрана. Эффекты попадания короткие, не скрывают телеграфы.

Мобильное управление: левый виртуальный стик — движение; по умолчанию автонаведение и автоматическая стрельба по ближайшей подходящей видимой цели в радиусе оружия. Правый стик — ручное прицеливание и стрельба, пока удерживается. После отпускания возврат к автонаведению, если оно включено в настройках. Стена исключает цель для автонаведения. Небольшая задержка переключения/гистерезис не дают прицелу метаться между равноудалёнными врагами. Не стрелять в пустоту при автоматическом режиме без цели. Во время ручного прицеливания можно стрелять без захваченной цели.

Отдельные кнопки аптечки, перезарядки, паузы. Аптечку разрешено использовать в движении, не отменяя стрельбу. Автоперезарядка при пустом магазине. В v1 нет прыжков, рывка, выносливости или обязательного ручного подбора монет.

ПК: WASD/стрелки, мышь и ЛКМ для ручной стрельбы; R — перезарядка, F — аптечка, Esc — пауза. Автоприцел включается в настройках и на ПК. Подсказки соответствуют текущему устройству ввода.

HUD: текущие/максимальные ХП, боезапас, волна и сектор, аптечка 0/1 и прогресс лечения, пауза. У края экрана — понятное предупреждение атаки за пределами видимости. На паузе — настройки, текущая сборка, продолжить, выйти в меню. Выход не удаляет безопасное сохранение.

## 4. Здоровье, броня и аптечка — обязательные правила

Базовое здоровье — 100. Единая шкала ХП: отдельной шкалы брони, прочности или ремонта нет. Броня увеличивает максимум ХП, НЕ даёт скрытого уменьшения урона. Особенности лёгкой/тяжёлой ветки отдельно указаны в данных.

Максимум = `(100 + armor_hp + armor_mastery_hp) × (1 + сумма бонусов max_hp_percent)`. Положительный прирост максимума при улучшении прибавляется и к текущему здоровью; пример 60/100 +40 → 100/140. При снижении максимума текущее здоровье ограничивается новым максимумом. В бою экипировку менять нельзя; в магазине здоровье полное, поэтому переключение брони не создаёт боевого лечения.

Аптечка: ОДНА на каждый раунд; остаток не переносится, запас устанавливается в 1, а не увеличивается на 1. Лечит ровно 20% максимального ХП за 4 секунды, со скоростью 5% максимального ХП/с. Максимум фиксировать при применении; восстанавливать непрерывно с учётом delta либо корректными тиками. На 200 максимальных ХП это 10 ХП/с, 40 ХП за полное действие. Частота кадров не должна менять результат. Внутреннее здоровье может быть дробным, HUD округляет только отображение.

Лечение ограничено максимумом; урон НЕ прерывает его. Аптечка не воскрешает, не даёт неуязвимости и не отменяет статусы. На полном здоровье применение отклоняется без расхода. Если эффект уже активен, повторное применение отклоняется. После смерти или завершения волны эффект очищается. При паузе лечение и все боевые таймеры остановлены.

Дополнительные аптечки в магазине пока НЕ реализовывать. Оставить расширяемую модель consumables, но не добавлять пустую кнопку покупки и платное продолжение. Ни пассивные модули, ни уровень магазина не изменяют подтверждённые 20% и 4 секунды.

Контактные атаки используют общую защиту от многократного контакта 0,35 с. Во время неё новые контактные удары не наносят урон; снаряды и зоны подчиняются своим интервалам попаданий. Нельзя получать контактный урон каждый physics frame. Одна обычная пуля наносит урон герою один раз и исчезает.

## 5. Оружие и стрельба

Все характеристики и цены — `data/balance_v1.json`. Оружие держится отдельным слоем; направление выстрела вычисляется из прицела, а не из текущего кадра тела. Коллизии и дальность независимы от размера рисунка. Выстрел проверяет стену между героем и дульной точкой, чтобы не стрелять сквозь угол.

Каталог v1:

| ID | Название | Роль |
|---|---|---|
| pistol | «Искра» | Стартовый надёжный пистолет |
| smg | «Шершень» | Ближний бой, высокая скорострельность и разброс |
| carbine | «Рубеж» | Универсальный карабин |
| shotgun | «Дуплет» | Семь дробин, силён вблизи |
| lmg | «Грохот» | Длинная очередь, долгая перезарядка |
| marksman | «Игла» | Точный медленный выстрел, пробитие одного дополнительного врага |
| flamethrower | «Горн» | Короткий конус пламени и горение |

У каждой ветки пять рангов: I «Кустарный», II «Полевой», III «Усиленный», IV «Профессиональный», V «Экспериментальный». Множитель ранга применяется к урону, а не ко всем статам сразу. Остальные характеристики сохраняются, пока в данных явно не переопределены. Цвет ранга дублируется цифрой/текстом.

Боезапас в магазине конечный, запас патронов бесконечный. Для дробовика одна атака тратит один патрон и выпускает семь дробин; крит определяется на выстрел и применяется к его дробинам. Для пробития хранить уже поражённые цели, чтобы одна пуля не била одного врага несколько раз.

Огнемёт: конус с проверкой прямой видимости, урон раз в 0,1 с, расход 10 единиц топлива/с. Горение одной цели от одного героя обновляет длительность до 2 с, а не суммирует бесконечные копии. Урон горения — 4/с на ранге I, умножается на ранг/мастерство/общий урон, не критует. На огнемётный тик тоже может приходиться обычный крит по базовому шансу; число частиц не определяет урон.

Стартовый крит 5%, множитель 1,5. Урон выстрела рассчитывается один раз, визуальные числа группировать, чтобы дробовик/огнемёт не создавали сотни Labels. Реальная длительная скорострельность учитывает перезарядку.

Все приобретённые за забег ветки сохраняются в компактном инвентаре. Активна одна пушка, переключение только в магазине. Повторно купить базу уже приобретённой ветки нельзя. Пистолет всегда остаётся резервным. Улучшения хранятся у конкретной ветки; смена активной не сбрасывает другие ветки.

## 6. Броня

Три ветки, пять рангов каждая. Покупка базы сразу позволяет экипировать ранг I. Названия рангов и бонусы ХП находятся в JSON.

- «Дозор»: лёгкая, меньше прибавка ХП, скорость +8%.
- «Оплот»: полевая, средняя прибавка ХП, без изменения скорости.
- «Бастион»: тяжёлая, большая прибавка ХП, скорость −10%.

Это проектное разнообразие, а не дополнительная защита: урон по броне не вычитается и не поглощается. Одновременно экипирована одна броня. Купленные ветки можно менять только между волнами, их прогресс сохраняется. Для графики сначала достаточно трёх читаемых силуэтов; рисовать 15 полных наборов анимаций не требуется.

## 7. Покупка частей и сборка

Карточка части имеет точные `family_id`, `target_rank`, цену и ID экземпляра предложения. Это «часть карабина III», а не универсальная случайная деталь. Для повышения II→III нужны три части этого семейства с target_rank=3. Купленная часть сразу попадает в счётчик; третья автоматически поглощает три части и повышает ранг. Нельзя пропускать ранги или смешивать семейства/целевые ранги. Улучшение сразу отражается в характеристиках и UI.

В v1 предлагать только части следующего ранга уже купленных веток оружия и брони, если этот целевой ранг доступен на текущем уровне магазина. Игрок не покупает бесполезные детали ещё не приобретённой ветки или ранга, который пока нельзя собрать. Можно улучшать неэкипированную, но купленную ветку. На V ранге её обычные части больше не генерируются.

Прогресс виден как 0/3, 1/3, 2/3. Продать неиспользованную часть можно за 50% фактически уплаченной за неё цены с округлением вниз. Хранить цену партии. Уже поглощённые части, базовые пушки и броню в v1 не продавать: не усложнять перерасчёт рангов. Продажа модуля описана отдельно.

Отдельной «заточки +5/+10» нет: роль последовательного усиления выполняют пять рангов и позднее мастерство. Не делать две дублирующие системы повышения одних и тех же статов.

## 8. Магазин и экономика

Шесть карточек. Категории: базовое снаряжение ещё не купленных веток, подходящие части, пассивные модули. Их вероятности и веса рангов заданы в JSON. Магазин персональный, без общего ограниченного пула для несуществующих соперников.

Купленное предложение исчезает, его место помечается «Куплено» и не заполняется автоматически. Покупка атомарна: проверка ID, состояния Shop, наличия денег, лимитов → списание → выдача → маркировка карточки → сохранение. Двойной тап не должен удвоить выдачу.

«Обновить всё — 10»: заменяет весь набор из шести предложений, включая пустые купленные места. Монеты списываются ровно один раз. Нет частичного обновления отдельной карточки.

«Сохранить предложения»: замок фиксирует оставшийся набор до следующей волны, вместе с купленными пустыми местами. Автоматическое обновление при входе в следующий магазин не происходит. Если вручную обновить заблокированный магазин, снять замок и создать новый набор; явно показать результат. Для заблокированного набора не перекидывать item IDs и цены при загрузке.

Дубликаты карточек частей/модулей в одном наборе допустимы; дубликаты одной базовой ветки внутри одного набора — нет. После покупки последней части остальные предложения этой ветки/целевого ранга становятся недоступными с текстом «Ранг уже собран», без списания денег. Не пересоздавать эти карточки скрытно.

Генерация: для каждого слота выбрать категорию по весу среди непустых допустимых категорий, затем ранг среди допустимых рангов по весам уровня магазина, затем предмет. При отсутствии кандидатов пере-нормировать веса; не зацикливаться и не генерировать недоступный ранг. Если всё обычное снаряжение собрано и модули достигли лимитов, можно показать карточки с текстом «Сборка завершена» и указать на мастерство; обновление за деньги отключить, если ни одного допустимого предложения нет.

Защита от неудачи: после трёх последовательных ПЛАТНЫХ обновлений без хотя бы одной части для активного оружия или экипированной брони четвёртое гарантирует одну такую часть, если соответствующее повышение открыто уровнем магазина. Счётчик сбрасывается, когда подходящая часть появилась; бесплатная смена волны счётчик не увеличивает. Нет гарантии конкретной ветки при двух возможных целях. Если целей нет, счётчик заморожен и UI предлагает повысить уровень магазина или заниматься модулями/мастерством.

Уровни магазина 1–5. Покупка повышения — отдельная кнопка, не занимает карточку. Цена и минимальная пройденная волна указаны в JSON. Повышение уровня увеличивает доступные ранги и количество слотов модулей, но не обновляет уже показанные предложения бесплатно. На уровне 5 кнопка корректно показывает максимум.

Доход за волну: `26 + min(2 × (global_wave − 1), 64) + interest`. Процент: `min(floor(coins_at_wave_start / 10), 10)`. Снимок coins_at_wave_start фиксируется после покупок и до боя, процент выплачивается только за победу. Бонус босса +30. Монеты за убийства/дочерних существ отдельно не выдаются. Нет фарма последнего призывателя. При поражении выплаты нет.

Цены v1 не увеличиваются скрытно во время забега. Полного сброса монет или экипировки при смене локации нет. Случайное содержимое, pity и все транзакции сохраняются, перезапуск приложения не должен давать бесплатный reroll.

## 9. Пассивные модули и сборки

В JSON 12 модулей, четыре набора по три РАЗНЫХ модуля. Приобретение первого экземпляра занимает слот и сразу активирует эффект. Повторная покупка такого же модуля повышает его уровень до 3 и не занимает новый слот; три копии соответствуют уровню 3, эффект за уровень складывается. Это отдельная система от трёх частей оружия.

При заполненных слотах новый вид модуля покупать нельзя без освобождения ячейки; показать причину, не списывать деньги. Уже установленный модуль можно улучшать. Продажа снимает модуль целиком, возвращает 50% общей фактически уплаченной за все его уровни цены и освобождает слот. Наборы пересчитываются немедленно, эффекты не остаются после продажи.

Набор включается при наличии всех трёх разных модулей хотя бы I уровня. Дубликаты одного вида не заменяют недостающий вид. Дополнительный эффект набора не умножается на уровень его модулей.

Наборы: «Штурм» (урон, темп, перезарядка), «Охотник» (криты и скорость пуль), «Живучесть» (ХП, контактная защита, медленная регенерация), «Манёвр» (скорость, дальность, ёмкость магазина). Точные бонусы и пределы в JSON. Медленная пассивная регенерация не меняет аптечку; начинает действовать после 8 с без любого урона и только в Combat.

Статы пересчитывать из исходных значений и текущих источников, а не последовательным умножением при каждой покупке. Учитывать caps; время перезарядки = `base_reload / (1 + reload_speed_bonus)`, а не base_reload×(1−bonus). Общая скорость игрока ограничена 0,75–1,35 базовой. Шанс крита ≤60%, множитель ≤2,5, бонус темпа ≤80%.

## 10. Мастерство после верхнего ранга

После V ранга активной пушки доступна отдельная покупка «Мастерство оружия»: +5% от урона V ранга этой ветки за покупку, аддитивно по счётчику. Аналогично V ранг экипированной брони открывает +5% от её ХП на V ранге за покупку. Цена 80 монет. Всего ОДНА покупка мастерства на магазин, на выбор оружие ИЛИ броня; это ограничение общее для всех веток и не сбрасывается переключением экипировки. До первой волны мастерство недоступно.

Формула урона ветки: `base_damage × rank_multiplier × (1 + 0.05 × weapon_mastery_count) × (1 + additive_damage_bonus)`. Формула ХП дана выше. Проценты мастерства не считаются от уже усиленного значения. Счётчики не сбрасываются при смене ветки/арены. Не заявлять, что эти коэффициенты уже сбалансированы на сотни волн: добавить средства быстрой проверки и тюнинга.

## 11. Враги и их конечные автоматы

Не использовать один ИИ «бежать к игроку» для всех. Общие состояния: SpawnWarning → Enter → ChooseAction/Move → Telegraph → Attack → Recovery; отдельное Dead. Враг не наносит урон во время SpawnWarning. Смерть отменяет ещё не выпущенные атаки. Роли используют собственные переходы и таймеры из JSON.

| Враг | Правило поведения |
|---|---|
| Бродяга | Идёт к герою, в ближнем радиусе делает видимый замах. Удар проверяет дистанцию в момент нанесения, а не в начале замаха |
| Бегун | Подбегает быстрее, перед укусом останавливается; после атаки есть короткая уязвимая пауза |
| Таран | На подходящей дистанции готовит рывок, фиксирует направление, движется по прямой без самонаведения. Столкновение со стеной завершает рывок; после него восстановление |
| Плевун | Старается держать среднюю дистанцию, отступает при сближении. Видимый плевок летит в зафиксированную позицию с небольшим разбросом |
| Стрелок | Ищет достижимую позицию с прямой видимостью, целится, делает очередь из трёх пуль, перезаряжается. Если стены мешают — меняет позицию, не стреляет сквозь них |
| Громила | Медленно подходит, отмечает круг тяжёлого удара. Герой, вышедший из круга до удара, не получает урон |
| Загонщик | Выбирает боковую точку относительно движения героя и ближайших союзников. Периодически переоценивает цель, не получает точное знание будущего ввода игрока |
| Носитель | Медленно сближается; после смерти создаёт двух слабых бегунов, занимающих учтённую часть бюджета. Они не создают новых носителей |

База HP, урона, скорости и атак указана в JSON. Враги не сталкиваются жёсткой стеной друг с другом: мягкое раздвижение, ограничение плотности и разные точки подхода. Путь пересчитывается с разными фазами и частотой 3–5 Гц, а не для каждого моба каждый кадр. Видимость и боевые попадания обновляются достаточно часто для корректности.

### Как стрелки промахиваются

1. Требуется прямая видимость до героя; при потере видимости до фиксации прицела стрелок отменяет подготовку.
2. Сначала видимый телеграф; точка фиксируется за 0,25 с до первого выстрела и остаётся одной на всю очередь. После фиксации можно закончить выстрел в старую точку, но пуля блокируется стенами.
3. Каждая пуля имеет ограниченный случайный угловой разброс из seeded RNG. Начальные стрелки целятся в последнюю известную позицию без упреждения.
4. Снаряды физически летят, не hitscan и не самонаводятся. Столкновения со стенами обязательны.
5. Поздние стрелки после волны 24 могут учитывать скорость героя с частичным упреждением до 0,25 с, но всё равно заранее фиксируют направление и сохраняют разброс минимум 4°.
6. У стрелка есть пауза/перезарядка; не уменьшать их до нуля.
7. Общий координатор допускает одновременную активную подготовку не более двух дальнобойных врагов в начале и четырёх в позднем забеге. Уже летящие снаряды сохраняются; лимит снарядов задан отдельно. Пока токен занят, остальные перемещаются/ждут, а не мгновенно атакуют все при освобождении: ввести фазовый разброс.

Для босса отдельный канал с лимитом, чтобы он не блокировал все обычные атаки навсегда и не создавал бесконечную стену снарядов. Атаки из-за экрана предваряются указателем направления. В первых секторах предпочтительно стрелять только из видимой зоны с небольшим полем за экраном.

## 12. Первое появление типов и составление волн

Бродяга доступен с волны 1; бегун с 3; таран с 5; плевун с 7; стрелок с 9; громила с 11; загонщик с 15; носитель с 19. При первом появлении типа дать небольшой текст/пиктограмму и не сочетать его сразу с максимально сложной группой.

Обычная волна получает бюджет угрозы `min(140, 10 + 3 × (global_wave−1))`. Стоимости типов в JSON. Бюджет распределяется на конечную очередь спавна с учётом доступных типов, архетипа волны, лимитов ролей и бюджета детей носителя. Заполнение остатка простыми врагами, без бесконечного цикла подборки неподходящих цен. Для носителя стоимость включает его двух детей.

Архетипы: «Рой» — много простых и немного быстрых; «Прорыв» — тараны/громилы с поддержкой; «Охота» — обходы и бегуны; «Перекрёстный огонь» — ограниченные стрелки/плевуны и ближняя охрана; «Передышка» — 75% бюджета. Все названия информативные, скрытый бюджет в обычном HUD не показывать. Первые две волны сектора легче среднего. Не повторять один архетип более двух раз подряд. Перед боссом не запускать максимальную комбинацию всех угроз.

Спавн несколькими порциями. Лимит живых врагов 36, одновременно дальнобойных 8, предупреждение появления 1 с, минимальное расстояние внешнего спавна от героя 260 игровых единиц, спавн в достижимой точке, предпочтительно за экраном. Для детей носителя и призыва босса допустимы видимые точки не ближе 120 единиц: отдельное предупреждение 1 с и ещё 0,5 с без атаки после появления. Если безопасной точки нет — отложить спавн, а не поместить моба в героя. Предварительные точки босса/опасных подкреплений всегда видимы и дают время реакции.

Появление врагов не должно зависеть от того, смотрит ли герой на точку; режиссёр не подстраивает бюджет под текущее ХП или использование аптечки. Seed забега и состояние RNG сохраняются. Отдельные RNG для боевого разброса, карты и магазина исключают смену ассортимента из-за количества частиц.

## 13. Бесконечный рост сложности и элита

`sector = floor((global_wave−1)/12)+1`, `local_wave = ((global_wave−1)%12)+1`. Локация выбирается по циклу из трёх, варианты раскладки — seeded. Экипировка и монеты сохраняются между секторами.

Множитель здоровья обычных врагов `1 + 0.055×(global_wave−1)`. Урона `1 + 0.025×(global_wave−1)`. Скорости `min(1.25, 1 + 0.004×(global_wave−1))`. Скорость тарана масштабируется по отдельному cap из JSON. Таймеры замаха/предупреждения не уменьшаются вместе со скоростью движения. Пули ускоряются максимум до 1,20 базовой скорости. Не вводить экспоненциальное умножение «прошлая волна × коэффициент».

Численность растёт до предела бюджета и одновременно живых мобов. Дальше сложность обеспечивают характеристики, роли, элита и условия карт. Любое ограничение должно применяться и к дочерним существам, и к боссовым подкреплениям.

С волны 18 элитный шанс от 8%, постепенно до 25%. Один обычный враг имеет максимум ОДНО свойство:

- «Проворный»: скорость ×1,12 поверх роста, но итоговая скорость преследования ≤1,45 базовой; здоровье ×0,85.
- «Живучий»: здоровье ×1,7, скорость ×0,90.
- «Нестабильный»: после гибели предупреждение взрыва 1 с, затем однократный урон в радиусе. Не взрываться без телеграфа в момент смерти.

Элита отмечена отдельной пиктограммой/контуром. Её стоимость бюджета удваивается; для носителя удваивается итоговая стоимость с детьми, сами дети обычные. Нельзя автоматически давать все свойства каждому врагу на поздних волнах. Не создавать невидимых врагов, случайную мгновенную смерть, обязательные попадания или постоянный пол без безопасного участка.

После ранга V герой развивается мастерством и модулями. Добавить ускоренный debug-переход на волны 24, 60, 120 с соответствующей тестовой экипировкой; в release эти команды скрыты. Для оценки баланса логировать длительность волны, DPS, попадания, закупки, источник смерти, но локально, с ротацией и без персональных данных.

## 14. Локации

Арена около 1600×1000 логических единиц с несколькими широкими маршрутами обхода. Геометрия проверяется на связность от стартовой точки. Генерировать из заранее проверенных раскладок, а не произвольно разбрасывать коллизии.

1. **Лесопилка**: штабеля, обломки техники, широкие петли прохода. Обучающая арена, первый сектор без фоновых опасных зон.
2. **Насосная станция**: бетонные блоки и трубы; периодические выбросы пара. Перед активацией 1,2 с предупреждения, опасная зона ограничена, хотя бы один маршрут обхода открыт. Пар может вредить врагам — правило одинаково отображается и тестируется.
3. **Затопленный двор**: островки и лужи. Вода замедляет героя и наземных врагов на 15%, обязательные маршруты полностью водой не перекрываются. Пули и лечение не замедляются.

По возвращении на локацию выбрать другую раскладку, освещение и допустимый модификатор. В v1 максимум один модификатор арены за сектор; эффекты не накапливаются бесконечно. Варианты: активные паровые клапаны, периодически включаемые отмеченные электрические зоны, заражённые лужи с ограниченной длительностью. Для каждого модификатора должен существовать безопасный путь, а стартовая зона очищается.

Декорации отделены от коллизий и телеграфов. Высокие объекты перед героем становятся полупрозрачными или скрывают верхнюю часть. Не требовать разрушения окружения, процедурных зданий, смены высот, прыжков или сложного лута.

## 15. Боссы

Каждая двенадцатая волна — один босс соответствующей локации, без полного обычного бюджета волны. Подкрепления ограничены восемью живыми одновременно и отдельным конечным бюджетом на фазу. Ни одна атака не покрывает всю арену без окна уклонения. Босс получает множители здоровья/урона глобальной волны; не применять их дважды через базовый спавнер.

- **Лесопилка — «Секач»**: рывок по фиксированной линии, широкий удар перед собой, короткая серия вызова бегунов. На 50% ХП атаки чередуются чаще, но телеграфы остаются читаемыми. После рывка окно стрельбы.
- **Насосная — «Котельщик»**: веер медленных снарядов с промежутками, отмеченные удары по трём зафиксированным точкам, вызов пара на части карты. Нельзя одновременно активировать пар и веер так, чтобы закрыть все промежутки.
- **Затопленный двор — «Матка»**: отмеченные кислотные лужи, ограниченный призыв, ближний толчок после подготовки. Старые лужи исчезают по времени; их число ограничено четырьмя.

Все атаки представлены отдельными действиями с параметрами и фазами. После смерти босса отменить незавершённые атаки, убрать опасные поля/пули/подкрепления, выдать награду один раз и открыть переход. Не оставлять героя погибать под меню наград.

## 16. Сохранения, пауза и завершение забега

Один локальный слот активного забега. Версия формата, seed, состояния генераторов, глобальная волна, локация и раскладка, монеты, уровень магазина, все ветки и части, модули, счётчики мастерства, lock, содержимое шести карточек, pity, статистика. Запись атомарная через временный файл и замену; резервная предыдущая валидная копия. Ошибка записи сообщается и логируется без потери последней копии.

В Shop сохранение после каждой транзакции/экипировки и при выходе. До старта волны сохранить checkpoint текущей экипировки и снимок стартовых монет. При закрытии приложения в бою следующий запуск повторяет ту же волну с её исходного состояния, не выдаёт награду и не меняет магазин. Это осознанный упрощённый suspend для v1; точное продолжение внутри боя не требуется. Игровая пауза/сворачивание немедленно останавливают симуляцию.

При штатном GameOver пометить забег завершённым до показа результатов. После загрузки нельзя продолжать заведомо проигранный забег из предыдущего checkpoint. Хранить локальный рекорд волны, время и историю последних 10 результатов отдельно от активного слота. Новый забег требует подтверждения, если есть активный.

Повреждённое сохранение → попытка восстановить резервную копию, затем понятный выбор нового забега. Не молча сбрасывать статистику/настройки. Миграция формата хотя бы через явную версию и обработку несовместимости.

## 17. Архитектура и производительность

Предпочтительные модули: RunState, WaveDirector, Economy/ShopService, Inventory/UpgradeService, StatCalculator, SaveService, AssetRegistry, CombatCoordinator. Не делать один скрипт на тысячи строк и десятки глобальных mutable-переменных. UI вызывает команды сервисов, а не напрямую изменяет монеты/ХП в нескольких местах.

Сцены: MainMenu, Game, Player, EnemyBase и роли, Projectile, Telegraph, ShopScreen, PauseScreen, ResultsScreen, BossBase. Данные предметов/врагов через валидируемые Resources или импорт JSON; стартовый JSON из пакета можно преобразовать в Resources, сохранив смысл и ID. Не парсить большие конфиги каждый кадр.

Object pooling для снарядов/частых эффектов, ограничение одновременно отображаемых чисел урона, пространственный поиск целей, разные частоты обновления ИИ. Проверка быстрых пуль лучом по пройденному сегменту или корректной непрерывной коллизией: пуля не должна перескакивать тонкую стену. Максимум вражеских пуль 120, игроковых 180, активных опасных полей 8. При достижении лимита атака корректно откладывается/сокращается, невидимые опасные пули не создаются.

Не создавать отдельный дорогой физический объект на каждый визуальный огонёк огнемёта. Симуляция на physics delta, корректная пауза, одинаковая скорость игры при 30/60/120 FPS. Утечки пулов, таймеров и signal-соединений между волнами недопустимы.

Целевой ориентир — 60 FPS на типичном Android среднего уровня, резервный режим 30 FPS и сниженные эффекты. Это цель, не заявленный результат без профилирования конкретного устройства. В отчёте указать фактическую среду измерения.

Экспорт: Android package `com.joepasqal.stalrena` как начальное проектное имя, landscape, без ненужных разрешений/сети. Не коммитить подписи, keystore, секреты и локальные пути. Подготовить export preset без приватных значений, README с требованиями выбранной версии движка. Debug APK собрать при наличии SDK/templates, иначе честно описать недостающие компоненты. Не считать desktop smoke test проверкой Android.

## 18. Графика и звук

Выполнять ART_CONTRACT.md. Все художественные ассеты заменяются через реестр, числовые характеристики от PNG не зависят. До поставки финальных PNG использовать читаемые процедурные заглушки соответствующего размера; явно пометить их как временные. Текст интерфейса живой, не запекать цены/ХП/названия в картинки.
