# STALRENA

Одиночная мобильная 2D-игра на выживание (Godot 4 / GDScript). Герой проходит волны на небольших аренах, между волнами тратит монеты в магазине (шесть предложений), собирает оружие и броню из частей, строит сборки пассивных модулей и сражается с боссами. После босса меняется локация, забег продолжается без конечной волны. Офлайн: без аккаунтов, PvP, рекламы и платежей.

## Запуск на ПК

1. Установите Godot **4.4.1** (стандартная версия, не .NET): <https://godotengine.org/download/archive/4.4.1-stable/>.
2. Клонируйте репозиторий и откройте `project.godot` в редакторе, либо запустите из консоли:

```bash
godot --path .
```

При первом открытии редактор сам импортирует ресурсы (папка `.godot/` в репозиторий не входит). Главная сцена — `res://scenes/main_menu.tscn`.

### Управление

| Действие | ПК | Телефон |
|---|---|---|
| Движение | WASD / стрелки | левый плавающий стик |
| Стрельба | автоприцел по ближайшей видимой цели в радиусе оружия (настройка); ручная — ЛКМ + мышь | автоприцел; правый стик — ручной прицел и огонь, пока удерживается |
| Перезарядка | R (также автоматически при пустом магазине) | кнопка «R» |
| Аптечка | F | кнопка с иконкой аптечки |
| Пауза | Esc | кнопка паузы |

Сенсорный интерфейс включается автоматически при наличии сенсорного экрана; на ПК его можно включить в «Настройки → Сенсорное управление → Всегда» (мышь работает как палец, только для проверки раскладки).

### Правила (кратко)

* Старт: 100 монет, «Искра» I, 100/100 ХП, без брони, магазин уровня 1, две ячейки модулей, одна аптечка.
* **Аптечка**: одна на раунд, без накопления; ровно 20% максимума ХП за 4 с (по 5%/с); максимум фиксируется при применении; урон не прерывает лечение; на полном ХП не расходуется.
* **Броня** увеличивает максимум ХП (единая шкала ХП) и не уменьшает урон: `(100 + ХП брони + мастерство) × (1 + бонусы модулей)`.
* Покупки, продажа, смена оружия/брони — только в магазине. «Обновить всё — 10» меняет все шесть карточек; «Сохранить предложения» фиксирует набор (с купленными пустыми местами) на следующую волну.
* Часть — это точно «часть карабина III»: три части поглощаются и повышают ранг ветки; защита от неудачи (pity) гарантирует часть после трёх платных обновлений без подходящей.
* Доход за волну: `26 + min(2·(волна−1), 64) + проценты (до 10, от монет на начало боя)`, босс +30. За убийства монет нет.
* Каждая 12-я волна — босс локации; сектор = 12 волн; локации по циклу: Лесопилка → Насосная станция → Затопленный двор.
* Автосохранение после каждой транзакции магазина и перед боем. Закрытие во время боя возвращает к началу той же волны, без повторной выплаты.

### Данные и тюнинг баланса

Все числа читаются из JSON при запуске (`GameData`), конфиг не парсится каждый кадр; при старте выполняется проверка согласованности (`GameData.validate()`). Менять баланс можно правкой `data/balance_v1.json` — формулы и ограничения (caps) в коде берут значения оттуда. Подтверждённые владельцем правила (аптечка, шесть карточек, броня = ХП, отсутствие PvP) не менять.

Средства быстрой проверки баланса:

* `StatCalc.weapon_dps()` — средний урон в секунду; в магазине (вкладка «Сборка») показан расчётный «урон/с».
* Автопилот `tests/sim.gd` прогоняет волны без отрисовки и печатает длительность, пики врагов/снарядов, HP.
* В debug-сборках в паузе есть кнопки перехода на волны **24 / 60 / 120** с тестовой экипировкой (`DebugTools`); в release скрыты.
* Локальный лог баланса: `user://balance_log.jsonl` (длительность волны, DPS, попадания, закупки, источник смерти; ротация по размеру, без персональных данных).

Места хранения на устройстве (`user://`): `run.json` (+ `.bak`, `.tmp`), `records.json`, `settings.json`, `balance_log.jsonl`, `diag.log`.

## Графика: заменяемые заглушки

Игра полностью играбельна без PNG: `AssetRegistry` по ID возвращает текстуру, кадры, pivot, масштаб и сокеты; если файла из `assets/asset_manifest_v1.json` нет, рисуется процедурная заглушка **того же логического размера** (одна запись в диагностику, без спама в бою). Чтобы заменить арт, положите PNG по `target_path` из manifest — баланс и коллизии не меняются (коллизии задаются данными раскладки). Подробности и раскладка атласа — `assets/art/README.md`. Фактический статус всех 58 записей — [`docs/ART_STATUS.md`](docs/ART_STATUS.md) (сейчас **ни одного готового PNG**, все — временные заглушки).

Шрифт — встроенный шрифт Godot 4 (поддерживает кириллицу); лицензии движка и его компонентов: <https://godotengine.org/license/> (в проект сторонние шрифты и аудио не добавлялись; звук — процедурные сигналы).

## Проверки

Запускаются из корня проекта (после `godot --headless --path . --import`):

```bash
# чистая логика: экономика, магазин, части, модули, мастерство, сохранения, волны, раскладки (6354 проверки)
godot --headless --path . --script res://tests/test_logic.gd

# поведение боя на реальной сцене: ИИ, лимиты, пауза, возобновление, боссы, оружие (100 проверок)
godot --headless --path . --quit-after 300000 res://tests/test_combat.tscn

# автопилот (НЕ человек): N волн подряд, опционально --loadout=24|60|120 --fps=30|60|120 --god
godot --headless --path . --quit-after 400000 res://tests/sim.tscn -- --waves=12 --seed=7

# замена графики через AssetRegistry (после добавления PNG и --import)
godot --headless --path . --quit-after 100 res://tests/test_art.tscn

# снимки реального проекта (нужен дисплей; пример под Xvfb) и замер кадра
xvfb-run -a godot --path . --rendering-driver opengl3 res://tests/shot.tscn -- --shot=shop --out=/tmp/shop.png
xvfb-run -a godot --path . --rendering-driver opengl3 res://tests/perf.tscn -- --loadout=119 --frames=900
```

Результаты и ограничения проверок — в [`docs/REPORT.md`](docs/REPORT.md).

## Экспорт Android

Требования (по документации Godot 4.4: <https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_android.html>):

1. Шаблоны экспорта **4.4.1.stable** (Editor → Manage Export Templates).
2. JDK **17** и Android SDK (platform-tools, build-tools, cmdline-tools, platform) — пути в Editor Settings → Export → Android.
3. Debug-keystore (редактор создаёт сам либо `keytool -genkeypair …`); **ключи подписи release в репозиторий не коммитятся**, в `export_presets.cfg` поля keystore пустые.
4. В проекте уже включено `rendering/textures/vram_compression/import_etc2_astc` (без этого экспорт Android отказывается стартовать без внятного сообщения).

```bash
mkdir -p build
godot --headless --path . --export-debug "Android debug" build/stalrena-debug.apk
adb install -r build/stalrena-debug.apk
```

Что фактически выполнено в среде разработки — в `docs/REPORT.md` (раздел «Android»). Сборка использует предсобранный шаблон (`gradle_build/use_gradle_build=false`), arm64-v8a, immersive-режим, без разрешений сети.
